# Aria 设计语言

这份文档是渲染层唯一的「长什么样」说明书。改界面之前先读它，改完跑
`npm run check:styles` —— 规则能被机器检查的部分都写成了脚本，不靠自觉。

设计目标只有一句：**看起来像原生 macOS / iOS 应用，而不是像网页**。
所有取舍都服从这一条。

---

## 一、三把尺子

界面上任何尺寸、颜色、动效都只能来自 `src/renderer/styles/tokens.css`。

| 尺子 | 令牌 | 说明 |
| --- | --- | --- |
| 间距 | `--space-1 … --space-6`（4 / 8 / 12 / 16 / 20 / 24） | 内边距、外边距、栅格间隙 |
| 圆角 | `--radius-2xs / xs / sm / md / lg / xl / 2xl / pill` | 4 / 6 / 8 / 10 / 14 / 18 / 24 / 999 |
| 高度 | `--elev-1 / 2 / 3` | 阴影层级，见下 |
| 动效 | `--dur-instant / fast / dur / slow` + `--ease-ios / out` | 时长与缓动 |

字号走 iOS 阶梯（`--text-caption … --text-large-title`），字体走
`--font-ui / --font-display / --font-mono`。

**为什么必须用令牌**：亮暗两套主题各维护一份值，写裸 `rgba(0,0,0,.28)`
等于只把当前主题调好，另一个主题必然失配；圆角写裸 px 则会在缩放、
不同组件之间慢慢长出十几种「差不多」的圆角。

### 左右基准线

**所有视图的左边线必须落在同一条竖线上**：工具栏标题、封面网格、设置页内容、
详情页头部，左右内边距一律 `24px`。

这条是踩出来的：共用工具栏曾经是 `20px`，而专辑/艺人页的封面网格与设置页内容都是
`24px` —— 于是**标题比内容少缩进 4px**，整排看着是歪的，却说不出哪里不对。
统一时改的是**共用的那一条**（`.view-toolbar`），三处一起对齐；
若反过来逐页去改内容，就得改三个地方，且下次新增视图还会再歪一次。

### 高度层级（阴影）

| 令牌 | 用在哪 |
| --- | --- |
| `--elev-1` | 贴住内容：歌曲行悬停、封面缩略图、分段控件滑块、灵动岛的滑块 |
| `--elev-2` | 浮在内容之上：悬浮控件、封面卡右侧浮出的播放键、灵动岛本体 |
| `--elev-3` | 浮在整个界面之上：弹层、菜单、队列面板、封面卡悬停 |
| `--shadow-artwork` | 独立的大画布投影，只给「正在播放」的巨型封面用 |

旧名字 `--shadow-popover / --shadow-thumb` 保留为别名
（`--elev-3` / `--elev-1`），新代码直接用 `--elev-*`。

允许的例外，只有三类：

1. **细环** `0 0 0 0.5px var(--separator)`、`0 0 0 1px …` —— 描边不是投影；
2. **取色发光** `0 6px 18px color-mix(in srgb, var(--accent) 40%, transparent)`
   —— 颜色由当前专辑的 `--tint` 决定（按「艺人 | 专辑」稳定生成，**不按封面取样**，见 README），无法预先定义；
3. **方向性边缘阴影**（如队列面板的 `-18px 0 40px`）—— 只在必要时用。

## 二、材料与层次

- **毛玻璃**的必要条件是「**玻璃后面有内容**」：后面是滚动内容、图像或窗口底色的光晕，
  否则只是白烧一次 `backdrop-filter`，看不出任何差别。
  侧边栏、播放条、标题栏是三个典型例子，**但不是全部** ——
  实测有 19 处用了毛玻璃（拖放浮层、帧率浮层、媒体墙上悬停出现的控件、正在播放页的背板、
  设置卡片…），全都是"玻璃盖在有内容的背景上"，都合理。
  可判定的形式是下面这一条，已做成检查（`npm run check:frosted`）：
  **同一个规则块里出现 `backdrop-filter` 时，背景不许是完全不透明的颜色**
  （不透明背景 + 毛玻璃 = 纯浪费；`background` 是 `rgba()` / `color-mix()` / `var()` /
  渐变、或者压根不写背景，都算合格）。
- **弹层**（菜单、选择器、队列）用 `--bg-popover` + `--shadow-popover`；
  内容卡片用 `--bg-elevated`。
- **分隔线**一律 `0.5px`（`0.5px solid var(--separator)`），1px 在
  高分屏上会显得比原生重（1.75× 屏上 1px 渲染成约 2 个物理像素）。
  已经做成 `check-styles` 的一条规则：**凡是用 `--separator` / `--separator-strong`
  当边框色的地方，粗细必须是 0.5px** —— 想用更粗的边就别用这个令牌，它的含义就是发丝线。
  实测 17 处（2026-10-17）全部合规；`.input` 那处原先漏成 1px，就是这条规则量出来的。
  （顺带发现：`.input` 这个类目前**没有任何元素在用** —— 见 `scripts/probes/probe-dead-css.js`
  的候选清单；接线还是删掉属于产品决定，没有擅自处理。）
- 深度优先靠**材料与投影**区分，不靠边框颜色深浅。
- **不要叠两层半透明材料**。内容舞台 `.stage` 已经是 `--bg-content`
  （约 72% 的白/黑），在它上面再放一层半透明白（或再套一层 `backdrop-filter`），
  合成结果会比周围亮一档 —— 看起来就是内容区顶部凭空多出一条横条。
  半透明只叠在**真背景**（窗口底色 + 光晕）上。要在这类表面上立结构，
  用 0.5px 分隔线，不加底色。
- **`.view-toolbar` 不加毛玻璃也不加底色**：它下面从来不会有内容滚过去
  （各视图的滚动容器都是它的兄弟节点），毛玻璃没有遮挡任务，只剩副作用；
  吸顶时只把 `border-bottom` 从 `transparent` 换成 `--separator`，并浮出紧凑标题。
- 布局上一对配套写法：**滚动容器 `flex: 1; min-height: 0`**，
  **固定高度的条 `flex: none`**。混着写（滚动容器用 `height: 100%`）会让 flex 列
  按比例压缩**所有**可压缩项 —— 实测把 52px 的工具栏压成 43px、大标题 83px 压成 72px，
  切视图时顶部那条的厚度会跟着变。

**卡片语言**（设置页的分组卡、专辑/艺人详情头部）统一为：
`--radius-xl` + `--elev-1` + `color-mix(in srgb, var(--bg-window) 约 52–86%, transparent)`
+ `backdrop-filter: blur(var(--blur))`。详情页头部虽然仍是扁平列表上方的横条，
也吃同一套 token —— 这样「分组面板」在全应用里是同一种材料，而不是每个页面各调一版。

**正在播放页的行序与那条示波器**（沉浸式可视化的落地方式，改动前先读这段）：

`.now-playing` 是一个三行栅格：`grid-template-rows: auto minmax(0, 1fr) var(--visualizer-h)`
—— **顶栏 / 主体 / 示波器**。封面铺底、玻璃、光晕都是绝对定位，不参与栅格；示波器元素
因此必须放在 DOM 的**最后**（它占第三行）。

为什么不是"绝对定位压在底部"：早先就是这么写的，781px 高的视口下量着刚好不重叠
（工具条底边 703、示波器顶边 709），但把窗口缩到最小高度 620 再量就是**重叠 43px**。
两个尺寸一拟合能看出工具条底边 ≈ 0.694×视口 + 161（它有自己的内容高度，不是贴着底边），
于是"视口低于约 761px 就会重叠"，而默认窗口才 780。占一行之后，重叠在结构上不可能发生。

四条硬规则：

1. **示波器是纯装饰**：`.visualizer` 必须 `pointer-events: none`。早先那版铺满底部又接收鼠标，
   把播放控件与底部工具条的点击全吃了（用户反馈「示波器阻挡 UI 按键」）。切换入口在**顶栏**那颗小按钮上。
2. **不要给它 z-index**：它是栅格自己的一行，和内容不可能重叠，写 z-index 只会掩盖布局问题。
   当年那版用 132px 铺到工具条下面，图标压在亮色频谱上读不清，只能再叠一层玻璃 ——
   不重叠就不需要那层玻璃（也就不会违反下面第 4 条）。
3. **窗口不够高时整条让位**：`@media (max-height: 680px)` 里把 `--visualizer-h` 归零并 `display: none`。
   阈值是量出来的：占行之后最小高度下工具条仍溢出主体 7px，解出"视口 ≥ 约 644px 才放得下"，
   取 680 留 36px 余量。默认窗口高 780，正常使用一直看得到它。
4. **示波器上面不要再放毛玻璃**：它每帧都在变，挂 `backdrop-filter` 等于每帧重算一次
   （同「毛玻璃只给三类表面」那条）。它自己的底色用 `color-mix(--tint …)` 的静态渐变即可。

改行高或改底部布局之后请重新量一遍：`npm run shots` 的 `[visualizer]` 探针会把
`stripTop`、工具条上下边、歌词区底边一起打出来；自检里另有三条守着几何
（不与工具条重叠、缩到最小高度不重叠、歌词不钻到条子底下）。

## 三、动效

三条硬规则：

1. **动的是位置和透明度，不是布局**。`transform` / `opacity` 走合成层，
   `width` / `top` 会触发布局。列表虚拟滚动靠 `top` 定位，所以绝不能在
   行上做 `top` 过渡。
2. **缓动只用 `--ease-ios`**（`cubic-bezier(0.32, 0.72, 0, 1)`）：起步快、
   收尾稳，是 iOS 的手感。需要「弹出」感时用 `--ease-out`。
3. **时长分级**：`--dur-fast`(150ms) 悬停反馈，`--dur`(260ms) 面板/滑块，
   `--dur-slow`(420ms) 整页切换。

### 悬停语言

悬停有统一的三件套：**底色 + 轻轻浮起 + 抬起阴影**。

```css
.row:hover {
  background: var(--bg-hover);
  transform: translateY(var(--lift));   /* -1.5px */
  box-shadow: var(--elev-1);
}
```

- 列表行用 `--lift`（-1.5px），封面卡用 `-3px scale(1.015)`，媒体墙格子
  不位移（会打乱网格对齐）。
- 浮起的行**不要自己的分隔线**（`::after { opacity: 0 }`），否则线会跟着飘。

导航类控件（侧边栏行 / 播放条按钮 / 标题栏按钮 / 灵动岛分段）不浮起、也不投影，
统一成更轻的一档：**悬停 `--fill-tertiary`、按下 `--fill-secondary`**，过渡走
`--dur-fast` + `--ease-ios`。

这四个位置的写法原本各不相同（底色来源不一、有的干脆没有过渡），移到上面时观感不一致。
顶栏按钮与灵动岛**只改底色与过渡、不动圆角**：那一带是命中测试最敏感的区域，
尺寸类改动要先跑 `npm run smoke` 再看。

### 重排（拖动排序）

列表重排一律用 FLIP：先记住每个节点的位置，改完 DOM 再算出位移、用 `transform`
把它按回原位，然后让它过渡回 0（`src/renderer/js/core/reorder.js`）。

- **不要用 `requestAnimationFrame` 等下一帧再开始过渡**：这个环境里 rAF 会被
  节流到 ~7fps，动画会晚 140ms 才开始。写完 `transform` 立刻读一次布局
  （强制同步回流）把起点钉住，就能同步开始。
- 被拖动的那一行不参与 FLIP —— 它由指针直接驱动，量位置前先清掉自己的
  `transform`，否则 `getBoundingClientRect()` 拿到的是已经位移过的值，越算越偏。
- 「减少动画」打开时不用额外写规则：时长被压到 0.001ms，动画自然消失。

### 滚动

有两个地方的内容位置是**算出来的**，不是用户滚出来的：歌词（把当前行推到正中）和
迷你歌词。它们都用 `transform: translateY` 移动内容，而不是 `scrollTop`。

代价是：`transform` 不产生滚动范围，容器的 `scrollTop` 会一直是 0。于是当跟随
把内容推上去一大截之后，用户能往下滚、却**翻不上去**（`scrollTop` 已经贴着 0）——
歌词曾经就是这个毛病。

规则：**只要用户开始手动滚动，就把位移交给 `scrollTop`**。

```js
// 交接：视觉位置不变（以前是 translateY，现在是 -scrollTop），方向从此都是原生滚动
inner.style.transform = 'translateY(0)'   // 必须在关掉 transition 之后做
scroller.scrollTop = Math.min(Math.max(-followY, 0), maxScrollTop())
```

回正（自动跟随恢复 / 点「回到当前」）时再折回去，并重新对齐。

配套的两点：滚动条是隐藏的，所以还要支持**抓住拖动**（`pointerdown/move/up` +
一个 3~5px 的阈值，幅度小于阈值仍然算点击 —— 歌词行是可以点了跳转的）；
拖动结束后紧跟的那一次 `click` 要吞掉，否则会顺带 seek 走。



### 减少动画

`减少动画` 设置会把 `html[data-reduce-motion="true"]` 写到根节点，并让所有
过渡时长变成 0.001ms。**但时长归零不等于效果消失**：`transform`、阴影这类
「静态」差异仍然会照常出现。所以凡是新增位移/阴影/缩放，都要同时补一条：

```css
html[data-reduce-motion='true'] .row:hover {
  transform: none;
  box-shadow: none;
}
```

保留底色变化即可 —— 它不产生运动。

### 导航只有一份

侧边栏与灵动岛**不会同时出现**：侧边栏开着时它就是导航，收起后由标题栏正中的
灵动岛接管（设置 → 外观里可以改成「侧边栏打开时也显示灵动岛」）。两者共用
`settings.sidebarOrder` 里的同一份顺序，所以在侧栏里拖动排序，灵动岛上的那几段也会
跟着换位（同样走 FLIP）。

收起侧栏有两个入口（侧栏头部的按钮、标题栏的按钮 / `Ctrl+B`），展开只有一个
（标题栏的按钮）—— 因为收起之后，侧栏里的按钮也一起不可见了。

## 四、组件约定

- **灵动岛**（`.island`）：标题栏正中的视图切换器，默认只在侧边栏收起时出现。平时只显示
  当前视图的文字，指向它（或键盘聚焦进来）才展开全部文字；滑块位置靠实测
  `offsetLeft` 计算，不写死宽度；当前视图不属于这四段（如设置页）时整条淡出。
  - **它这块必须能拖窗口**：标题栏用 `.titlebar > * { -webkit-app-region: no-drag }`
    把每个子元素都设成不可拖，所以灵动岛要显式改回 `drag`（里面的分段按钮才是
    `no-drag`）。否则标题栏正中会留下一块「拖不动」的死区 —— 而且它在隐藏时
    （`opacity: 0`）照样生效，用户看到的就是「鼠标在这一块拖窗口没反应」。
  - **底色用 `--fill-floating`**：深色下 `--fill-quaternary`（14% 灰）压在近黑标题栏上
    几乎看不出边界，看起来像「灵动岛不见了」。这个令牌是亮暗成对定义的
    （深 0.22 / 亮 0.11），再配一条 `0 0 0 0.5px var(--separator)` 的细环定边界。
- **侧边栏**：头部是「Aria + 收起按钮」，`Ctrl+B` 或标题栏按钮同样能收起。
  收起时整列宽度归零（`.app` 的 grid 过渡）+ 内容向左淡出 + 边框变透明
  （否则会在左边留下一条 0.5px 的竖线）。
- **设置页**（`ui/views/settings-view.js`）：**两层结构** ——
  主标题（侧栏「设置」）→ 子页面 → 子标题（音乐库 / 播放与音效 / 外观与系统 / 在线与扩展 / 关于）
  → 标签框（一组同类设置）→ 设置项（一行标题 + 一个控件）。
  - **标签框必须单列、上下排列**。只把容器的 `columns` 改成 1 **不够**：
    `column-count` 与 `column-width` 并存时列数按宽度推算，实测仍然排成三列、
    右边两框被挤出可视区。真正的解法是给标签框加 `column-span: all`，让它跨满整行。
  - **标签框顺序按 `SECTIONS` 重排**（在 `groupNodes` 声明之后做）。它们在 DOM 里原本是零散的
    （「外观」排在「均衡器/播放」前面），于是点「播放与音效」会落到「外观与系统」的地盘，
    用户直观感受就是「这两个放反了」。
  - **点子标题 = 滚动定位**：把对应标签框顶到最上面，并高亮该子标题。
    位置用 `getBoundingClientRect()` 差值算 —— `offsetTop` 在单列 + `column-span` 布局下不可靠，
    曾把「在线与扩展」判成「关于」。
  - **高亮以点击为准**：点完强制保持该子标题，并在滚动动画结束后再确认一次；
    滚动联动只在**手动滚轮**时才接管（用 `wheel` 判定）。否则点击定位会被联动改写。
  - **设置内搜索**复用全局 `.search` 外观（放大镜 + 输入 + 清空），只保留设置页特有的
    匹配计数与回车跳转；它**不写 `ui.query`**（那是过滤资料库的，写进去会把歌曲/专辑页一起改掉）。
  - **最近搜索另存一份** `settings.settingsSearchHistory`，不与歌曲页的 `searchHistory` 共用：
    两边词义完全不同，混在一起会让搜过的设置词把歌曲页历史挤掉。自检里有一条专门守这个。
- **自建播放列表**：侧栏里的一段，条目就是用户自己的列表；新建/重命名用同一个
  小输入面板（Electron 里没有 `window.prompt`），加歌走曲目右键菜单。
  打开一个列表时它就是一个「来源」（`ui.source.type === 'playlist'`），
  与文件夹来源同构 —— 列表页、播放、随机播放都不用写第二套。
  新建入口有两处（组头的 + 和一条「新建播放列表」行）：组头那颗曾经因为
  `.sidebar__row-action { opacity: 0 }`（只在行悬停时出现）而永远不可见 ——
  **组头不是行，放进去的按钮要自己保证可见**。
- **列表**：虚拟滚动，行绝对定位在 `index * --row-h` 处，行高固定。
- **多选工具条**（`.tracklist__selection`）：挂在 `createTrackList` 内部，所以歌曲列表、
  专辑详情、艺人详情、自建播放列表都有，不用各写一套。**两首以上才出现** ——
  单击本来总有选中项，单选也弹就是噪音（单首的操作在右键菜单里）。
  选中态沿用 `--accent-soft` 底色（和「正在播放」那行同一个语言）。
- **勾选框**（`.track-row__check` / `.tracklist__check`）：列表最左侧一列，**只在多选模式里
  出现**（`.tracklist.is-selecting`）。选中打勾、没选空着；表头那颗是全选，部分选中时
  用一条短横（`is-partial`）和「全选」区分。
  - **它不能是入口**。第一版让它「行悬停就露出来、点了就进多选」，结果列表的
    「点一下选中、双击播放」和勾选互相打架，用户会莫名其妙进入一个自己没想进的状态。
    隐藏时除了 `opacity: 0` 还要 `pointer-events: none` —— 否则它仍是一个看不见的
    点击目标，点在行左边缘就会误进多选。
  - 入口放在**列表右上角的「⋯」**（`ui/list-menu.js`，歌曲页与专辑/艺人详情页都有）
    和歌曲右键菜单里，都是明确的一次操作。
- **多选模式是显式进入的**（`ui.selecting`）：普通点击永远只是「选中这一首」。
  入口：列表右上角「⋯」→ 选择多个歌曲、右键 → 开始多选、`Ctrl/Shift` 点击、`Ctrl+A`
  （后两个本身就表达多选意图）。模式内点行 = 勾选 / 取消勾选；勾选项清空时模式自动退出
  （不留「开着但一个没选」的中间态）。
  例外的优先级：**「单击歌曲直接播放」打开时以它为准**（那是用户明确要的行为），
  多选走勾选框 / Ctrl / Shift。
- **序号列和勾选框列是两个格子**：`paintRow` 必须用建行时存下来的引用
  （`row.__index`），**不能用 `row.children[0]`** —— 左边加过一列之后，
  `children[0]` 就变成勾选框了，曾因此把序号和播放键画进勾选框、序号那列反而空着。
- **分段控件 / 灵动岛**：同心圆角 —— 外圆角 = 内圆角 + padding，
  例如容器 `--radius-md` + 2px padding → 滑块 `--radius-sm`。
- **滚动条自己画**（`ui/widgets/scroll-indicator.js` + `.scrollbar`）：原生滚动条做不出
  「悬浮药丸 + 悬停变宽 + 拖动再放大」，而这是灵动岛的语言，两处观感要同源
  （`--fill-floating` / `--fill-floating-strong` + `0.5px` 描边 + 模糊底）。
  三档状态：静止（细而淡）→ 悬停或滚动 `is-active`（变宽变亮）→ 拖动 `is-dragging`
  （再放大并浮起来）。原生那条必须同时关掉（`scrollbar-width: none` +
  `::-webkit-scrollbar { width: 0 }`），否则会出现两条。内容不够一屏时整条隐藏。
- **声音均衡器**（`core/equalizer.js`）：节点一次建好，切预设只改参数 ——
  重建整条链会爆音，而媒体元素只能 `createMediaElementSource` 一次。
  关闭 = 参数归零（EQ 全 0、干声 100%、压缩与饱和旁路），不是拆链。
  音频图**懒创建**：没开均衡器、插件也没要可视化时一个节点都不建，播放走原生路径；
  开机时如果均衡器是开着的，要等第一次播放（用户手势）再建，否则 AudioContext 只能挂起。

## 六、颜色来源（`--tint`）

**一条规则**：凡是"跟着封面变"的颜色，只能读 `--tint` / `--tint-2` / `--tint-soft`，
不许自己再算一份。写入点只有 `core/artwork.js` 的 `applyTint()`。

| 读它的地方 | 文件 |
| --- | --- |
| 页面底部两团光晕 | `styles/base.css` |
| 正在播放页光晕 + 示波器条 | `styles/nowplaying.css` |
| 设置页选中态 / 搜索命中 | `styles/settings.css` |
| 示波器波形颜色 | `js/ui/widgets/visualizer.js` 的 `accent()` |

取色（`resolveColor(track)`）按设置 `tintSource` 分两档：

- `cover`（默认）：从封面取样。逐像素按饱和度加权算色相，同时累加每个像素自己的
  **S / L** —— 不要"先把 RGB 平均再转 HSL"，彩色图平均下来必然是灰的（这条踩过，见 CONVENTIONS）。
  取样前跳过近黑/近白像素；取样后若平均饱和 < 0.12 或平均亮度 > 0.85 / < 0.08 就回退。
- `palette`：由「艺人 | 专辑」哈希出的稳定配色（不联网、不看封面）。

**稳定性**：颜色按 `artworkKey(track)`（`e:艺人|专辑` / `f:路径`）缓存，不按 blob URL ——
blob URL 每次加载都不同，按它缓存等于没缓存。

**背景不许有两套颜色**：`.now-playing__art-bg` 是封面模糊图，它的 `::after` 叠了一层 30% 的
`--tint` 色调，把背景拉回与光晕/示波器同一个色系。

**过渡**：`--tint` 用 `@property` 注册成 `<color>`，`:root` 上有 240ms 过渡；
「减少动画」打开时过渡置零。
