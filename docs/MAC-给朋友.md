# 给在 Mac 上帮忙测试的朋友

嗨！这是一个自己写着玩的本地音乐播放器（Aria）。想请你在 Mac 上跑一下看看有没有问题。
**它没有上架、也没有签名**（就是自己人之间测），所以第一次打开时系统会拦一下，照下面做就行。

---

## 一、先看看你手上是哪种文件

### 情况 A：拿到的是 `Aria-…-arm64.dmg` 或 `Aria-…-x64.dmg`

跳到第二节。

> 怎么选：屏幕左上角 苹果菜单 →「关于本机」，看「芯片」。
> 写 **Apple M…** 用 `arm64`；写 **Intel** 用 `x64`。

### 情况 B：拿到的是一个源码压缩包（`aria-…-mac-source.zip`）

那需要你在终端里跑两条命令把它打成 app（大约 3–5 分钟，会下载约 200MB 依赖）：

1. 先装 Node.js（选一个就行）：
   - 打开 https://nodejs.org → 下载 **LTS** 版的 `.pkg`，双击装完；
   - 或者如果你装了 Homebrew：`brew install node`
2. 解压源码包，在终端里 `cd` 进那个文件夹，然后：

   ```bash
   npm install
   npm run dist:mac
   ```

3. 跑完之后，`release/` 目录里会出现 `Aria-…-arm64.dmg`（或 `-x64.dmg`），回到第二节。

---

## 二、安装并第一次打开

1. 双击 `.dmg`，把里面的 **Aria** 拖进「应用程序」；
2. 打开「应用程序」，**右键点 Aria →「打开」**，在弹出的框里再点一次「打开」；
   - 直接用双击会被拦下来说「无法验证开发者」，这是正常的。
3. 如果系统只说「移到废纸篓」：打开 **系统设置 → 隐私与安全性**，
   往下滚一点会看到「已阻止使用 Aria」，点 **「仍要打开」**；
4. 万一还是打不开（提示「已损坏」），在终端里跑一次下面这行，然后再打开：

   ```bash
   xattr -cr /Applications/Aria.app
   ```

   这是未签名应用的老毛病，只需要做一次。

| --- | --- | --- |
| 1 | 窗口左上角 | 有原生的**红黄绿三个圆点**，标题不压在圆点上 |
| 2 | 加音乐文件夹 | 设置 → 音乐文件夹 → 添加一个放音频的文件夹，能扫出歌。**扫不到歌就先看有没有一条黄色提示**（它会告诉你是没权限还是路径没了） |

## 四、有问题怎么告诉我

- **截图最有用**（界面问题请深色/浅色各来一张）。
- 卡住或崩溃：打开「控制台」App → 搜索 `Aria`，把相关几行复制给我。
- 想看到更细的日志，可以在终端里跑：

  ```bash
  /Applications/Aria.app/Contents/MacOS/Aria --dev
  ```

  它会打开一个开发者工具窗口，里面的红字就是线索。

## 五、先说在前面：这些不是 bug

- 第一次打开要「右键 → 打开」，因为没签名（见第二节）。
- **音乐如果放在「文稿」「桌面」「下载」里，可能扫不出来** —— 这是 macOS 的权限限制（未授权的应用读不了这几个目录）。
  遇到这种情应用会弹一条**黄色提示**告诉你怎么做：去「系统设置 → 隐私与安全性 → 文件与文件夹」允许 Aria，
  或者把音乐放进**「音乐」文件夹**（`~/Music`，这里不受限制）。外接硬盘同理。
- 键盘上的媒体键（⏯）可能没反应 —— 未签名的应用在 macOS 上不一定能接管它，
  用右上角菜单栏图标里的控制一定可以。
- 没有锁屏/控制中心的「正在播放」集成（那需要额外的原生模块，这次没做）。
