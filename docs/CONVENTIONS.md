# Aria 开发规范

这份文档记录**怎么做改动**（流程、验证、踩过的坑），界面"长什么样"的规则在
[docs/DESIGN.md](DESIGN.md)，扩展点写法在 [docs/EXTENDING.md](EXTENDING.md)。

一句话版本：**改完跑 `npm run check`；动界面再加 `npm run smoke` + `npm run shots` 并真的看图；一次提交一件事。**

---

## 一、提交规范

- **一次提交只做一件事**，消息用中文，写清三件事：**改了什么 / 为什么 / 验证了什么**。
  例：`fix(设置): 标签框按子标题顺序重排 —— 原来物理顺序是零散的（外观排在均衡器/播放之前），
  导致点「播放与音效」落到「外观与系统」的地盘；验证：自检 161/161 通过`。
- **打包失败就不要提交"打包"那条提交**。真的踩过：某个版本打包因网络失败，
  但 `chore(打包): x.y.z` 照常提交了，于是 git 历史里有一个**从来没有产物**的版本号。
- **小改动不要打包**。`npm run dist` 只在阶段边界做（一次几分钟，产出上百 MB）。
- 提交前确认**工作区干净**、`npm run check` 全绿。

## 二、验证流水线（按可信度从高到低）

| 手段 | 什么时候用 | 可信度 |
| --- | --- | --- |
| `npm run check` | **每次改动必跑**：未使用 import、注入脚本语法、样式令牌、亮暗成对、左右基准线、裸值棘轮、**文档本地链接可解析** | 高（确定性） |
| 定向探针（注入代码读真实 DOM） | 验证某个具体行为（"点子标题是否滚到位"） | 高 |
| `npm run shots` | 界面改动后出截图 —— **必须打开图看**，不能靠脑补 | 高（但要看） |
| `npm run smoke` | 交互链路是否仍然可用 | 中（会抖动，见下） |
| `node scripts/probes/probe-*.js` | 数据类问题（元数据 / 歌词 / 艺人字段） | 高 |

### 自检抖动了怎么办

`npm run smoke` 结果会波动（同一提交连跑两次可能 161/161 与 159/161）。
**先判断是环境还是代码**：

1. 看日志里的 `GPU 相关行`（正常是 0）与帧率记录（开发机约 117fps）；
2. 看失败项是否**轮换**（这次是"侧栏"，下次是"灵动岛"）——轮换＝抖动，
   固定同一条＝大概是真问题；
3. 抖动多半来自**并发**：同时跑别的重活、或用脚本站连着跑好几遍。
   空载单跑一次通常就是绿。

### 自检卡住（长时间一行输出都没有）

**症状**：日志停在两百来字节，连 `=== Aria 自检 ===` 都不打印。
**原因**：自动化配置目录被写坏了 —— 最常见的是**自检运行中强制结束了 electron**。
**处理**：删掉 `%TEMP%\aria-dev-profile` 再跑（会自动重建；首次要重扫资料库，所以第一轮偏慢）。
这条提示也写在 `src/main/smoke.js` 里。

## 三、改文件的规矩（这一节最省钱）

1. **不要用 `node -e` 改文件**。PowerShell 对引号、反斜杠、模板字符串的转义规则
   和 JS 不一样，写着写着就把脚本喂坏了（本次踩了三次，每次都要重来）。
   一律：**写成脚本文件**，或者用编辑工具做**字面替换**。
2. **不要用 PowerShell 改 JSON**。`Get-Content -Raw | ConvertFrom-Json` 会按 ANSI
   读 UTF-8，中文变乱码、写回去就是截断的文件（真的把 `package.json` 写坏过一次）。
   改 JSON 一律用 **Node**：`JSON.parse` → 改字段 → `JSON.stringify(p, null, 2)`。
3. **PowerShell 里 `$name:` 会被当成盘符**。`"$f:$n"` 报错/出错值，写成 `"${f}:${n}"`。
4. **改含模板字符串的代码，用 PowerShell 单引号字符串最稳**：单引号里反引号与 `$` 都是字面量，
   `${...}`、反引号都不会被 shell 吃掉（这条是踩了四次 `node -e` 之后总结的）。
   同理，改 JSON 用 Node、改代码用单引号字符串或脚本文件。
5. 改完立刻 `node --check <文件>`；`.js` 改完再跑 `node scripts/checks/check-injected.js`
   （注入到渲染层的代码写在模板字符串里，多一个括号肉眼很难发现）。

### 不要照抄带 Context 的缩进

`Select-String -Context`（以及各种 grep 的上下文展示）会在每行前面加自己的前缀，
**那不是文件的缩进**。照着抄去做字符串替换，必然匹配不到 —— 这条连续坑了两次。

做法：替换锚点用**不含缩进的内容**（例如整行去掉前导空格后的部分），
或者先用 read 工具看一眼真实文本。

配套习惯：**先全部匹配到、再一次性写盘**。脚本没匹配全时就中止，
这样「改了 2/3」不会把文件写坏 —— 这个模式也连续兜住两次了。

## 四、代码约定（每一条都踩过）

1. **先声明后使用**。`const` / `let` 必须在引用之前 —— 把重排代码插到 `groupNodes`
   声明之前，渲染层直接 `ReferenceError`，界面整个起不来。
2. **位置计算用 `getBoundingClientRect()` 的差值，不要 `offsetTop`**。
   在多列 + `column-span` 布局下 `offsetTop` 不可靠，曾把「在线与扩展」判成「关于」。
3. **多列布局里要让块跨满整行用 `column-span: all`**。只把容器改成 `columns: 1`
   没用：`column-count` 与 `column-width` 并存时列数按宽度推算，实测仍然排成三列。
4. **搜索类组件不要写 `ui.query`**。那是"过滤资料库"的开关，写进去会把歌曲页 /
   专辑页一起改掉；页面内搜索（如设置页）自己维护状态。
5. **语义不同的历史分开存**。设置页搜索历史用 `settings.settingsSearchHistory`，
   与歌曲页的 `settings.searchHistory` 分开 —— 混用会让一边把另一边挤掉。
   有一条自检专门守这个。
6. **视图内的临时状态放模块作用域**（如 `activeSection`），不要放在每次渲染都重建的
   闭包里，否则重渲染后状态就丢了。
7. **事件监听只绑一次**。视图会渲染多次，用标志位挡住（`navScrollBound` 那种写法）。
8. **兜底要有出口**。长流程（如自检）要把结论放在 `exit` / `uncaughtException` /
   `unhandledRejection` 的兜底里，否则中途中断就什么结论都没有。

## 五、设计规范

- 界面规则以 **[docs/DESIGN.md](DESIGN.md)** 为准，改界面前先读它。
- 能机器检查的规则一律写进 `scripts/checks/check-styles.js`：
  圆角/阴影必须走令牌、`var()` 必须已定义、亮暗两套必须成对、
  **左右基准线 24px**、**裸值棘轮**（颜色/时长/字号总量只减不增）、
  **缓动只走 `--ease-*`**（`linear` 例外：进度条这类匀速动画）、
  **内联样式里不许写颜色**、**卡片必须引用同一组令牌**
- **新增检查的前置条件：零误报**。一条会误报的检查，第二次就会被人绕过 ——
  那还不如没有。有历史存量时用"棘轮"（只统计总量、不增加就过），
  而不是一刀切禁掉。
- 机器挡不住的部分（审美、层级判断）写进 DESIGN.md，靠截图人工看。

## 六、环境坑

| 现象 | 原因 / 处理 |
| --- | --- |
| `electron .` 退化成 Node，报 `Cannot read properties of undefined (reading 'commandLine')` | shell 里带着 `ELECTRON_RUN_AS_NODE=1`。用 `Remove-Item Env:ELECTRON_RUN_AS_NODE`（**置空不生效**） |
| `npm install` 时 Electron 二进制下载失败 | 从 `%LOCALAPPDATA%\electron\Cache\electron-v<版本>-win32-x64.zip` 解压到 `node_modules/electron/dist`，并在 `node_modules/electron/path.txt` 写 `electron.exe` |
| 打包卡在下载 | 走国内镜像：`ELECTRON_MIRROR` + `ELECTRON_BUILDER_BINARIES_MIRROR`（见 `README` 的打包说明），不需要代理 |
| Electron 版本对不上 | `package.json` 里声明的版本要与 `node_modules/electron/dist/version` 一致，否则排查时会看错版本 |
| 应用在某个目录下完全起不来 | 见下面第七节 |

## 七、排查顺序（故障 / 性能）

1. **先拿到真实报错**。不要只看"没反应"就猜；在真正的控制台里跑一次，
   `[main]` / `[renderer:error]` 会直接说是哪一行。
   （本次教训：绕了很久才去要日志。）
2. **换环境交叉验证**。"所有版本、零输出、连崩溃日志都没有"这种组合，
   优先用**另一个账户 / 另一个目录**试一次 —— 本次那个"应用完全起不来"最终
   就是靠把项目换到别的目录定位的，跟代码无关。
3. **再二分提交**。用 `git checkout <commit>` + 同一条命令复现，比读代码快。
   注意排除抖动：同一提交连跑两次，结论一致才算数。
4. **性能问题先量再改**。用 `npm run perf` 的 A/B 对照（同一轮里改 CSS），
   别凭感觉换写法；线上（开发机）帧率上限、rAF 节流都会影响读数。

## 八、别做的事（都是真实事故）

### 不要为了整洁去合并重复定义的选择器

同一个选择器在同一个文件里写多遍时，**后写的覆盖前面的**；把后面的声明并进第一处，
等于把这段声明**在层叠里的位置往前挪** —— 于是它和「夹在两条规则之间的其它选择器」的胜负关系就变了。

实测：一次把全库 18 处重复选择器合并（脚本还断言了「每个选择器按属性合并的结果不变」），
`npm run smoke` 从 **161/161 掉到 150/161** —— 聚焦块尺寸错、列表滚不动、`translateY=NaN`…
这类债务**留给需要改那条规则的人顺手清理**即可，别专门去做。

### 深度搜索的字段清单写在三处，改一处要同步三处

真正参与匹配的字段只在 `src/renderer/js/core/selectors.js` 的深度匹配那一串里定义，
但它被三个地方**描述**着：`selectors.js` 顶部的注释、歌曲页搜索面板的提示文案
（`ui/views/library-view.js` 里那句「还会搜索歌词文件，以及…」）、README 的搜索一节。

这三处没有机器守卫 —— 想做也做不了零误报的检查（文案是给人读的措辞，不是字段列表），
所以靠流程兜：**改字段时顺手把三处一起改**。历史上就漂移过：代码里早就支持
所在文件夹 / 路径 / 码率 / 采样率 / 无损，而提示与 README 只写到「目录、编码格式」。
### 自检不要拿「当前值」当「默认值」

`settingsService.get()` 读的是**当前持久化值**，而自检在同一轮里自己就会改设置 ——
把当前值当默认值来断言，就成了**自我污染**：同一份配置目录里第二次运行必然失败，
只在全新目录下才会通过。历史实例：「联网总开关」检查读 `onlineFeatures` 判默认，
而它自己在末尾把开关改成了 `false`（改成读代码默认 `DEFAULTS.onlineFeatures` 才修好）。

**判定方式：连跑两次**。这类 bug 单次通过说明不了任何问题；两次都绿才算数。
这也是判断「是代码坏了还是环境抖动」最省事的办法 —— 两次失败项一致才值得往下查。

### 截图不能当"像素级无变化"的判据

`npm run shots` 的图会随**正在播放的曲目、封面、播放状态**变化 —— 同一份代码两次出图，
PNG 也会不一样。想证明"渲染没变"，得用 `npm run audit` 的计算样式/几何对比，
而且**必须等页面加载完**（第一次基线只抓到 17 行，实际应有 810 行，那次 diff 148 处全是假警报）。

### `.select` 是包裹层类，不是加在 `<select>` 上的修饰类

正确写法：`h('div', { class: 'select' }, h('select', { … }))` —— 
配色与右侧那个箭头都由包裹层的 `.select::after` / `.select select` 提供（components.css）。
写成 `<select class="select">` 不会报错，但下拉会退化成浏览器默认样式（做睡眠定时器时踩过）。
